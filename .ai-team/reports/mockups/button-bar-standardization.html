Button Bar Standardization

Save/Cancel buttons appear inconsistently across GIFBot pages. Some pages have buttons at the top, some at the bottom, some at both locations. Button styling varies between Bootstrap and MudBlazor. This mockup establishes a standard pattern.

Current Problems

Problem 1: Duplicate Button Bars

CountdownTimer.razor and BackdropEditor.razor have Save/Cancel buttons at BOTH the top and bottom of tabs. This is redundant and confusing.

Problem 2: Bootstrap Buttons

Most pages use btn btn-secondary and btn btn-primary instead of MudButton, creating visual inconsistency.

Problem 3: No Spacing

Bootstrap buttons touch each other with no gap, unlike MudBlazor's default spacing.

Problem 4: Type Attribute Issues

Mix of type="reset" and type="submit" on Cancel buttons causes unexpected form behavior.
